0.8.1

## 0.8.1

- **Fixed: Auto-Salvage wrenched the switches that make a POI work.** The wall switch beside a\
  garage door, a push button, a valve handle, a key rack, a wire or timer relay, a pressure plate, a\
  quest generator — the game tags every one of them as salvage, exactly like a sink, so the module\
  took them. You do not see it happen and you cannot undo it: none of those blocks can be crafted or\
  looted, so the door that switch opened never opens again, for the life of the save, for every\
  player who comes to that POI after you.

  Auto-Salvage now leaves switches, buttons, relays, pressure plates, quest triggers and powered\
  doors, lights and traps alone. It matches on what the block *is* rather than a list of names, so a\
  modded switch is covered too. Set `SalvageSwitches="1"` if you want the old behaviour back.

- **Fixed: the no-salvaging-in-a-land-claim rule had three ways to quietly not apply.** Auto-Salvage\
  has always been meant to work unclaimed ground only, and it asked the game the obvious question —\
  but the game answers "unclaimed" for claimed ground in three cases: the claim block sits in a\
  chunk nobody has loaded, it is not that player's main claim block, or its owner has been offline\
  longer than the server's land claim expiry. On a server the last one is the one that bites: go\
  away for a week and a drone could strip your base with your claim block still standing in it.

  The module now reads the claim list directly, which has none of those holes. A claim block that\
  exists protects its ground, whoever owns it and whenever they last logged in. There is no setting\
  for this one, and there should not be.

## 0.8.0

- **Switch a module off without pulling it out of the drone.** Hold **E** on the drone, pick\
  **Talk**, then **Automation modules...** — every automation function gets its own row saying\
  whether it is running, and clicking the row flips it. The module stays in its slot and keeps its\
  quality, so putting it back costs nothing. A **Switch every module back on** row clears the lot,\
  and the setting survives relogs and server restarts.

  A function with no module fitted reads **no module installed** instead of offering a switch, so\
  the menu can't be mistaken for a settings screen — these are still modules you have to find the\
  schematic for, craft and fit.

  This was asked for as a hotkey. It couldn't be one: key bindings and the radial wheel are both\
  client-side, so either would have meant shipping a client download and ending this mod's\
  "clients install nothing" rule. The wheel's own **Talk** entry was the way in without breaking\
  that — the menu works on a completely vanilla client, because the server pushes it.

  One honest limit: the switches are **per player, not per drone**, so running two drones switches\
  a function off on both. The "no module installed" rows are per drone — they describe whichever\
  drone you're standing at.

## 0.7.5

- **Fixed: Auto-Harvest handed you a free seed every time it reaped a crop.** A crop drops its own\
  young stage when harvested, and the module put that seed in the drone's bag *and* planted a\
  separate fresh one in the empty plot. Two seeds where the crop produced one.

  That is not what harvesting by hand does. Vanilla leaves a reaped plot bare, and the seed the crop\
  hands you is the one you spend putting it back. So a drone farm quietly produced a spare seed per\
  crop per cycle — on a 27-plot field, 27 seeds a cycle, compounding into more plots.

  The replant is now paid for by the seed the drone just reaped. Only that one seed is consumed, so\
  a perk-boosted harvest still hands over the surplus, and your produce is untouched.

- **Auto-Harvest now explains itself when it reaps nothing.** Set `Debug="1"` in\
  *droneautomation.xml* and a pass that harvests nothing prints what it actually saw: where it\
  scanned from, its reach after quality scaling, how many grown crops were in range, how many were\
  outside your claim, and how many had no replant — naming one.

  Worth knowing if you ever test this by hand: crops come in two flavours. The ones growing wild in\
  the world carry no seed, so the drone deliberately leaves them standing rather than reap a plot it\
  cannot replant. Only crops grown on a farm plot are harvested. A drone ignoring a field of wild\
  corn is working correctly.

  The setting ships off, so nothing changes unless you turn it on.

## 0.7.4

- **Fixed: v0.7.3 could not run on game 3.0.0, which it claimed to support.** If you are on 3.0.0,\
  Auto-Loot — the module most people install this for — threw the first time the drone tried to put\
  something in a bag, and kept throwing. Every other module that stores an item was in the same\
  boat. 3.0.1 and 3.1 were unaffected.

  Nothing in the source was wrong. The released DLL was compiled against a newer game than the\
  oldest one on its label, and that is enough on its own. 3.0.1 introduced `InventoryBase` as a base\
  class above the inventory types and moved `AddItem` and `TryStackItem` up onto it, so a build made\
  against 3.0.1 or later points those calls at `InventoryBase` — a type 3.0.0 has never heard of.

  The direction matters and it is worth stating plainly, because it is the part that is easy to get\
  backwards. A reference made against a *derived* type still resolves on newer builds, because the\
  runtime walks up the hierarchy to find the member. A reference made against a *base* type that was\
  introduced later resolves on nothing older, because the type itself is missing. So the build has\
  to be made against the **oldest** version claimed, not the newest.

  What makes this worth a release note rather than a one-line fix is that every check passed. The\
  build succeeded. `refcheck.py` against 3.1 passed — it was only ever run against the newest build.\
  A live 3.1 dedicated server booted the mod cleanly. None of it could see the version that broke.

- `package.sh` **now refuses to build a zip whose label it cannot back up.** New\
  `tools/check_game_versions.py` reads `GAME_VERSIONS`, locates a game build for each version named,\
  and resolves every external reference in the DLL against all of them. A claimed version with no\
  build available fails too, rather than quietly passing — an unverified claim is the whole bug.\
  `GAME_BUILDS` says where the builds live (default `~/7dtd-servers`); `SKIP_REF_CHECK=1` skips it\
  for anyone packaging without them.

- `BUILD.md` **now records which game build each release was compiled against.** Without it the\
  hash table could not be reproduced even from the right commit, which made the reproducibility\
  claim thinner than it looked.
